# سكوب كوفي — النسخة الكاملة لـ Vercel وSupabase

هذه نسخة التصميم الأصلي كاملة، وليست صفحة HTML تجريبية. تستخدم Next.js وReact، وتحافظ على ألوان سكوب وخطي Noto Sans Arabic وDM Sans والرسومات الأصلية. لا تتطلب حسابًا أو رابطًا تابعًا لأي منصة محادثة.

## ما الذي يوجد داخل النسخة؟

- منيو بثلاثة أقسام، بحث، صور، أحجام وخيارات السكر والإضافات وأسعارها.
- قهوة تركية: سادة/وسط/حلوة، ماء، وكرواسان كبداية. أسعارها غير محددة إلى أن يضعها المدير.
- سلة وكميات وملاحظات، واستلام من الكشك أو توصيل داخل الجامعة فقط.
- الدفع عند الاستلام. الدفع الإلكتروني غير مفعّل.
- حسابات مستقلة للمدير والكاشير ورئيس الكادر والموظف: إنشاء برقم الهاتف، تغيير كلمة المرور، قفل وفتح الحساب، وحذفه. يستطيع كل موظف تغيير كلمة مروره من «حسابي».
- توليد رقم دور سريع بضغطة واحدة، دون هاتف أو مبلغ أو تفاصيل، والاسم اختياري.
- تذكرة 58/80 مم تحمل رقم الدور وQR خاص بمتابعة الطلب.
- تسلسل واحد لأرقام طلبات الموقع والدور المباشر، مصدره قاعدة البيانات.
- تم الاستلام، قيد التحضير، جاهز، قيد التوصيل، وتم التسليم.
- تنبيه صوتي أثناء فتح الصفحة بعد تفعيله. لا تتضمن هذه النسخة إشعارات خلفية أو إرسال SMS/WhatsApp تلقائيًا.
- إدارة المنتجات والصور والنفاد، وباقات العروض وتواريخها.
- شريط إعلانات متحرك قابل للتعديل، مع التحكم بالسرعة.
- إعدادات نقاط الولاء كمسودة فقط؛ احتساب النقاط والتحقق من رقم هاتف الزبون وصرف المكافآت مؤجل.
- تحميل إعلان PDF بحجمي A4 وA5 وباركود المنيو، باستخدام عنوان الموقع الجديد تلقائيًا.

## مهم قبل الرفع

ارفع **كل الملفات والمجلدات**، ولا تكتف باستبدال CustomerApp.jsx وStaffDashboard.jsx وindex.html وsupabaseClient.js. الملف package.json ومجلدا app وlib وملفات Supabase ضرورية لعمل التطبيق.

المشروع القديم احتوى صفحة index.html مستقلة. الواجهة الرئيسية الآن هي app/page.tsx، وindex.html مسار توافق فقط. يجب أن يكون إعداد Framework Preset في Vercel هو **Next.js**.

احتفظ بنسخة من مستودعك وقاعدة بياناتك قبل الاستيراد. الجداول الجديدة تبدأ بـ scoop_، ولا تُحذف أو تُعدّل الجداول القديمة categories/products/orders تلقائيًا.

## الخطوة 1 — تجهيز Supabase

1. افتح مشروع scoop-cafe في Supabase.
2. افتح **SQL Editor → New query**.
3. انسخ كامل الملف `supabase/001_scoop_schema.sql` وشغّله.
4. في استعلام جديد، شغّل `supabase/002_scoop_storage.sql` لإنشاء مكان حفظ الصور.
5. من **Project Settings → API Keys** انسخ **service_role أو Secret key الخاص بالخادم**. لا تنشره داخل GitHub ولا في ملفات الواجهة.

تستخدم النسخة مفتاح الخادم عبر API الخاص بالتطبيق. الجداول الجديدة ليست مفتوحة للقراءة والكتابة المباشرة بالمفتاح العام. كل عمليات الكاشير والإدارة تمر بفحص الصلاحيات على الخادم.

## الخطوة 2 — تجهيز حساب المدير

على حاسبتك، داخل مجلد المشروع:

```sh
npm ci
npm run create-admin
```

اختر اسم مستخدم مثل admin وكلمة مرور من 10 أحرف على الأقل. الأداة لا تعرض أو تحفظ كلمة المرور، بل تنتج سطر JSON يحتوي بصمتها. احتفظ بكلمة المرور التي اخترتها، وانسخ سطر JSON فقط إلى متغير STAFF_ADMIN_BOOTSTRAP في الخطوة التالية.

هذه بيئة مستقلة؛ حساب المدير وكلمة مروره في النسخة السابقة لا ينتقلان تلقائيًا إلى قاعدة Supabase الجديدة.

## الخطوة 3 — إعداد Vercel

افتح مشروعك في Vercel، ثم **Settings**:

### Build and Deployment

- Framework Preset: **Next.js**
- Root Directory: جذر المستودع (اتركه فارغًا إذا كانت الملفات في الجذر).
- Build Command: `npm run build`
- Install Command: `npm ci`
- Output Directory: إعداد Next.js الافتراضي. احذف أي قيمة قديمة مثل dist أو public.
- Node.js: **22.x** أو إصدار أحدث مدعوم.

### Environment Variables

أضف القيم إلى Production وPreview حسب البيئة التي ستجربها:

| الاسم | القيمة |
| --- | --- |
| SUPABASE_URL | https://uhdwrmfylbqgakwxznds.supabase.co |
| SUPABASE_SERVICE_ROLE_KEY | مفتاح الخادم الصحيح من Supabase |
| STAFF_ADMIN_BOOTSTRAP | سطر JSON الناتج من npm run create-admin |
| SITE_URL | https://scoop-cafe.vercel.app |

لا يلزم NEXT_PUBLIC_SUPABASE_ANON_KEY لعمل المنيو والكاشير؛ ملف supabaseClient.js موجود للتوافق والتوسعة فقط. لا تضع مفتاح service_role في أي متغير يبدأ بـ NEXT_PUBLIC_.

روابط الباركود والتذاكر تستخدم https://scoop-cafe.vercel.app عند فتح أي نشر على Vercel. يمكن تغيير العنوان العام مستقبلًا من SITE_URL ثم إعادة النشر. ضع عنوان الإنتاج العام في SITE_URL، ولا تضع رابط نشر طويلًا محميًا.

بعد حفظ المتغيرات، نفّذ **Redeploy**. رفع الملفات وحده لا يجهز قاعدة البيانات أو المتغيرات تلقائيًا.

## الخطوة 4 — فتح الموقع

استخدم عنوان النشر Production الذي يعرضه Vercel، وليس رابط لوحة vercel.com:

- `/` : واجهة الزبون، بلا تسجيل دخول.
- `/admin` : الكاشير والإدارة، باسم المستخدم وكلمة المرور التي اخترتها.
- `/track?order=...` : متابعة الطلب من باركوده الخاص.
- `/api/health` : فحص الربط. status=ready وdatabase=true يعنيان أن ربط القاعدة اكتمل. admin=true يعني وجود إعداد حساب المدير، وليس اختبار كلمة مروره.

إذا ظهر طلب تسجيل دخول إلى Vercel للزبائن، راجع **Settings → Deployment Protection** وتأكد من أن عنوان الإنتاج المقصود متاح للجمهور؛ لا تعطّل الحماية عن بيئات داخلية لا تريد نشرها.

## الخطوة 5 — تشغيل المقهى

1. ادخل /admin.
2. من **المنتجات** حدّد الأسعار وارفع الصور المطلوبة.
3. من **الإعدادات** أضف الهاتف والإنستغرام وأجرة التوصيل لاحقًا، وفعّل استقبال الطلبات حين تكون جاهزًا.
4. من **الكادر** أضف اسم الموظف ورقم هاتفه العراقي وكلمة مرور ودوره (كاشير، رئيس الكادر، موظف). يقبل الرقم بصيغة 07 أو +964، وكذلك الأرقام العربية، ويُحفظ بصيغة موحدة لمنع التكرار.
   - يمكن للمدير قفل الحساب وفتحه أو تغيير كلمة مروره أو حذفه نهائيًا. تغيير كلمة المرور لا يفتح الحساب المقفل تلقائيًا.
   - القفل والحذف وتغيير كلمة المرور تلغي صلاحية الجلسات القديمة. حذف الحساب لا يحذف الطلبات السابقة.
   - كل موظف يغيّر كلمة مروره من **حسابي** بعد إدخال كلمة مروره الحالية.
   - يبقى دخول المدير الحالي باسم admin صالحًا؛ لا يلزم إنشاء المدير من جديد أو تغيير إعدادات Supabase لهذا التحديث.
5. من **العروض** أنشئ الباقات إن رغبت.
6. من **الشريط** أضف الرسائل وفعّل ظهورها.
7. جرّب طلب موقع ودورًا سريعًا، ثم مراحل التجهيز والباركود والطباعة.
8. من **الدعاية** نزّل الإعلان والباركود من عنوان الإنتاج النهائي، ثم اطبعهما.

الطباعة تفتح نافذة اختيار طابعة الجهاز. على iPad يلزم طابعة متوافقة مع AirPrint أو حل طباعة مناسب. ليست طباعة صامتة ولا اتصالًا مباشرًا بطابعة USB من أي هاتف.

## استيراد بيانات النسخة القديمة — اختياري

بعد تشغيل ملفات SQL، أنشئ `.env.local` على جهازك وفق `.env.example` وأدخل فيه عنوان Supabase ومفتاح الخادم؛ لا ترفعه إلى المستودع.

لاستيراد المنتجات والأقسام والإضافات من الجداول القديمة:

```sh
npm run import-legacy
```

ولإضافة أرشيف الطلبات القديم أيضًا:

```sh
npm run import-legacy -- --with-orders
```

الاستيراد لا يحذف الجداول القديمة ولا يكتب فوق المنتجات التي سبق استيرادها. الطلبات المستوردة تحصل على أرقام تسلسل جديدة، ويُحفظ رقمها القديم داخل بياناتها للرجوع إليه. لا يشمل ذلك بيانات قاعدة النسخة السابقة المستضافة خارج مشروع Supabase هذا.

## التشغيل محليًا والفحص

```sh
npm ci
npm run dev
npm run typecheck
npm test
npm run build
```

تعمل معاينة المنيو الأساسية دون مفاتيح لعرض التصميم، لكن الطلبات والدخول يحتاجان إعداد Supabase أعلاه. لا تُستخدم ذاكرة المتصفح لحفظ طلبات المقهى أو حسابات الكادر.
